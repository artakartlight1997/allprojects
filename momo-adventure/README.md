# りなの大冒険

Jetpack Compose の Canvas だけで作った横スクロールアクションゲーム。
画像アセットは一切使わず、キャラも背景もすべて図形で描画している。

## 遊びかた

| 操作 | 動作 |
|---|---|
| ◀ ▶ | 歩く |
| ▲ | ジャンプ（長押しで高く跳ぶ） |

- 体力は 3。敵・トゲ・スライムに **3 回**当たるまで残機は減らない
  （落下だけは 1 回でミス）
- 敵は**上から踏む**とやっつけられる。ただし **とげのすけ** は踏めない
- 空中で連続して踏むと**コンボ**になり、得点が倍々に増える
- 触られると 1 ミス。落下・トゲ・溶岩も 1 ミス
- 旗の**チェックポイント**に触れておくと、ミスしてもそこから再開できる
- 早くクリアするほど**タイムボーナス**が付く

## 9面をやさしくした

「よぞらのとう」は空中の足場だけで進む面で、落ちると 1 ミスになるため
子どもがクリアできなかった。次のように直してある。

| | 前 | 後 |
|---|---|---|
| 空中の足場の幅 | 3〜4 タイル | **5〜6 タイル** |
| 足場のすき間 | 4〜5 タイル | **2 タイル**（ジャンプは 5.96 タイル跳べる） |
| 敵 | 14 体 | **7 体** |
| 追いかけてくる敵 | 2 体 | **0 体** |
| 初見殺しの仕掛け | 6 か所 | **0 か所** |
| 中間地点 | 1 か所 | **5 か所** |
| アイテム | 5 個 | **9 個**（はねを 2 つ・ハートを 2 つ） |

移動床は足場の**真上**に置いたので、乗りそこねても下の足場に落ちるだけで
ミスにならない。使わなくても先へ進める。

「右へ進み、前に穴か壁か敵があれば跳ぶ」だけの自動プレイ 8 回で、
**6 回ゴールに到達**（平均 2.3 ミス）。同じ自動プレイでは 4〜8 面は
1 回もクリアできないので、9面はいまや後半でいちばんやさしい。

## コンテニュー（つづきから）

クリアしたステージは、次に開いたときにタイトルで選んで始められる。
最後まで行けなくても、毎回1面からやり直さずにすむようにするため。

- タイトルに **ステージえらび** の 1〜10 が並ぶ。行けたところまでが選べる
- 前回の続きが最初から選ばれている
- **ゲームオーバーでも 1 面まで戻されない**。やられたステージから選び直せる
- ボタンの大きさと最高スコアも一緒におぼえる

記録はブラウザの `localStorage`（キーは `rina-adventure.v1`）に入れている。
同じ端末の同じブラウザなら残るが、別の端末には引きつがれない。
中身は「行けたステージ・最高スコア・ボタンの大きさ・全クリ回数」だけ。

タイトルの中身は多いので、画面の低い端末では全体の高さを足し算してから
入らないぶんだけ縮める。「はじめる」が下にはみ出さないようにするため
（568×320 まで確認済み）。

## 画面が小さい端末向けの配慮

- 操作ボタンの大きさは画面の高さに対する比率で決めている
- タイトル画面で **ボタンの大きさ（小 / 中 / 大）** を切り替えられる
- りながボタンと重なる位置にいるあいだ、ボタンを薄くする。
  ステージ開始直後はカメラが左端で止まるため特に重なりやすい
- 画面が低い端末では HUD の文字とステージ名表示を縮める

## しかけ

- **ジャンプ台** — 乗ると通常の 2 倍以上の高さまで打ち上がる
- **移動床** — 横または縦に往復する。乗ると一緒に運ばれる
- **?ブロック** — 下から叩くとコインが出る
- **チェックポイント** — 触れると復活地点になる

## ボスの登場演出

ボスに 11 タイルまで近づくと、一度だけ登場演出が入る。演出中はゲームが
止まり、集中線・広がる輪・きらきら・名前の表示が出て、ボスがその場で
跳ねる。倒しかたのヒントも一緒に出す。

## コインが取れるかの検査

`tools/genlevels.py` は、すべてのコインが跳んで届く位置にあるかも調べる。
足場から 3.4 タイル上・水平 5 タイル以内なら届くものとし、移動床や
ジャンプ台がある列は上限を緩める。厳密な経路探索ではないが、明らかに
届かない配置は検出できる。現在は全 10 ステージで 0 件。

## 初見殺し

**ステージ4以降**に、初見では避けにくい仕掛けを 2〜3 個ずつ置いてある（全 31 箇所）。
ステージ1〜3 は操作を覚える面なので、知らないと避けられない要素は入れていない。
**ステージ9 にも置いていない**（下の「9面をやさしくした」）。
どれも一度知れば対処でき、近くにチェックポイントを置いている。

| 仕掛け | 動き | 見分けかた |
|---|---|---|
| もろい足場 | 乗ると 0.45 秒で崩れ落ちる。3 秒後に戻る | ひび割れた白っぽい足場 |
| とつぜんトゲ | 3 タイル以内に近づくと地面から生えてくる | 地面にうっすら継ぎ目と点が見える |
| どんぐり | 真下を通ると落ちてくる。着地後は歩き回る | 頭上に細い糸でぶら下がっている |

生成スクリプトは、仕掛けが既存の敵・アイテム・チェックポイントを
上書きしていないかも検証する（実際にこの検証で 3 件の消失を検出した）。

## 実機で動かす手順

1. このリポジトリに push すると GitHub Actions が自動でビルドする
   （`.github/workflows/android.yml`）
2. 数分後、**Releases** の `dev` プレリリースに APK が添付される
3. スマホのブラウザで開き、`momo-adventure.apk` をタップしてインストール

リリースには 3 つの APK が付く。

| ファイル | 中身 |
|---|---|
| `momo-adventure.apk` | 配布用。R8 で圧縮したもの |
| `hello-android.apk` | 上と同一。以前の URL を壊さないためのコピー |
| `momo-adventure-debug.apk` | 圧縮なしの予備。R8 が原因の不具合が疑われるときに使う |

release ビルドも debug と同じ鍵で署名している。鍵を変えると既存の
インストールを上書きできなくなるため。

配布ページ（短い URL・インストール手順つき）:
https://artakartlight1997.github.io/allprojects

リリース一覧:
https://github.com/artakartlight1997/allprojects/releases/tag/dev

配布ページの中身は `site/index.html`。`.github/workflows/pages.yml` が
main への push で GitHub Pages へ配信する。同じサイトの `/nihon/` に
「りなの全国制覇」（`nihon-quest/site`）も入る。

`site/404.html` は、無い URL を開いたときに GitHub Pages が出すページ。
打ちまちがえても両方のゲームへ行けるようにしてある。ページ内のリンクは
`/allprojects/...` の絶対パスにしている。相対リンクだと、末尾のスラッシュが
無い URL（`.../allprojects`）から踏んだときに行き先がずれるため。

**最初に一度だけ手動設定が必要**: リポジトリの Settings → Pages →
Build and deployment → Source を「GitHub Actions」にする。
Actions の自動トークンには Pages を新規作成する権限がないため、
この操作だけはワークフローから行えない。

`hello-android.apk` は以前のダウンロード URL を壊さないための同名コピー。
中身は `momo-adventure.apk` と同一なのでどちらを入れても同じ。

## Web 版

`site/play/` に、同じゲームを JavaScript + HTML Canvas で実装したものがある。
サーバー処理は不要で、静的ファイルを置くだけで動く。iPhone や PC でも遊べる。

https://artakartlight1997.github.io/allprojects/play/

| ファイル | 役割 |
|---|---|
| `game.js` | 物理・当たり判定・ゲーム進行（Android 版の Game.kt に対応） |
| `render.js` | キャラと背景の描画（Render.kt に対応） |
| `ui.js` | HUD・操作ボタン・エンディング・入力・ループ |
| `levels.js` | ステージデータ。`tools/genlevels.py` が Kotlin 版と同時に生成する |

物理定数は Android 版と同じ値を使っている。ステージデータは生成元が同じ
なので、マップが両者でズレることはない。それ以外のコードは独立しているので、
片方を直しても自動では反映されない。

**ステージ2 のパパは Web 版だけの要素。** Android 版の Level は未知の文字を
空白として読み飛ばすため、Android 版のステージ2 にはボスが出ない（遊べなく
なることはない）。今は Web 版を主にしているのでこの差は許容している。

縦画面のときは「よこ向きにしてね」と表示してゲームを止める。iPhone の
Safari には画面の向きを固定する手段がないため。

全画面は、タイトルの「ぜんがめんにする」か「はじめる」で切り替わる
（全画面 API はユーザー操作がないと呼べないため）。iPhone の Safari は
要素の全画面表示に対応していないので、その場合は「ホーム画面に追加」を
案内する。追加してから開けばブラウザのバーが出ない。
ノッチのある端末で操作ボタンが隠れないよう、セーフエリアも避けている。

## ステージデータについて

`app/src/main/java/com/example/momo/Levels.kt` は
`tools/genlevels.py` が生成する。**手で編集しないこと。**

```
python3 tools/genlevels.py app/src/main/java/com/example/momo/Levels.kt
```

このスクリプトはマップを組み立てるだけでなく、次を物理定数から計算して検証し、
1 つでも引っかかれば生成せずに終了する。

- 跳び越せない隙間がないか（移動床・ジャンプ台がある場所は上限を緩める）
- 登れない段差がないか
- 敵・ゴール・チェックポイントが空中に浮いていないか
- 開始地点の近く（10 タイル以内）に敵がいないか

ジャンプ性能（`Game.kt` の `GRAVITY` / `JUMP_VELOCITY` / `MOVE_SPEED`）や
移動床の振れ幅を変えたときは、スクリプト冒頭の定数とコメントも合わせて
更新すること。

## 構成

| 項目 | 値 |
|---|---|
| 言語 / UI | Kotlin + Jetpack Compose (Canvas) |
| 画面 | 横向き固定・フルスクリーン |
| compileSdk / targetSdk | 35 |
| minSdk | 24 (Android 7.0 以上) |
| AGP / Kotlin / Gradle | 8.7.3 / 2.1.0 / 8.9 |
| 配布ビルド | release（R8 で圧縮・リソース削減） |

`applicationId` は `com.example.helloandroid` のまま変えていない。
変えると別アプリ扱いになり、以前入れたアプリが端末に残るため。
同じ ID・同じ署名なので、インストールすると上書き更新される。

## debug.keystore について

`app/debug.keystore` をリポジトリに含めて署名を固定している。
これがないとビルドのたびに署名が変わり、再インストール時に
「アプリを更新できません（署名が一致しません）」で弾かれる。

debug ビルド専用の鍵なので、公開しても問題ない。
Google Play に出す段階になったら、release 用の鍵を別途作って
GitHub Secrets に置くこと（この鍵は絶対にコミットしない）。

## ブラウザのキャッシュ避け

`site/play/index.html` の script タグには `?v=9` のような番号を付けている。
js を直したらこの番号を増やす。増やさないと、前に遊んだ人のブラウザが
古い js を読み込んだままになり、直したはずの不具合が直って見えない。
