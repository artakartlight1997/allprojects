# リナのスライムラボ

材料を入れてスライムを作るゲーム。**入れた量で手ざわりも色も変わる**。
できたスライムは のばす・ぷにぷに・バウンド であそべて、たなに残せる。
ブラウザだけで動く（サーバー処理なし・インストール不要）。

https://artakartlight1997.github.io/allprojects/slime/

## 遊びかた

1. **材料のびんをゆびでつかんで**、ボウルの上まで運ぶ。かたむいて出てくる
2. 出る場所は**ゆびのところ**。だから好きな場所にたらせる
3. ボウルの中を**ゆびでぐるぐる**すると、なぞったところだけまざる
4. 「できた！」で できあがり。名前・手ざわり・できばえ★が出る
5. 「あそぶ」で **のばす / ぷにぷに / バウンド** の3つ
6. たなに **12こ**まで残せる。あとから出してあそべる

## 自分の手でまぜる

ボウルの中身を **120このつぶ**であらわしている。つぶ1こ1こが
「自分と同じ中身でボウルをいっぱいにしたら何色になるか」を持っていて、
**ぜんぶの平均がいまの配合そのもの**になるようにしてある。

大事なのは「かってにはまざらない」こと。

- たらした絵の具は**そこにとどまる**。ボウルの中で青と黄が別々に見える
- ゆびでなぞったところだけ、つぶ同士が色をわけあう
- 青のとなりに黄をたらしてまぜると、**さかいめから緑になっていく**のが見える
- まぜ足りないと**しま模様がスライムに残る**（名前も「マーブル〜」になる）

色のやりとりはおたがい同じ量ずつなので、合計は変わらない。だから
**ぐるぐるまぜて全部そろったとき、できあがりの色とぴったり一致する**。
（テストで確認：つぶの平均 6.77 ＝ 実際の配合 6.77）

「まぜ」メーターは手を動かした量ではなく、**本当に色がそろったか**を
はかっている。まぜる手ごたえと色のそろい具合、両方がいる。

## のばす・ぷにぷに ― スライムそのものが620個の粒

**スライムは描いた丸ではない。300個の粒でできている**（`fluid.js`）。
だから引っぱれば本体ごと形が変わるし、ちぎれるし、くっつくし、
放っておけば机に広がる。粒には「こう動け」と書いていない。
書いてあるのは物理法則だけ。

**① 縮まない液体**（PBF / Position Based Fluids, Macklin & Müller 2013）
まわりの混み具合を一定に保つ、という条件をくり返し解く。それだけ。

**② 粘弾性バネ**（Clavet らの粘弾性流体モデル）
水はほうっておくとぺたんと広がる。スライムが広がらないのは、液体なのに
ゴムのような性質も持っているから。そこで粒どうしをバネでつなぐ。ただし
ふつうのバネではなく、**伸ばしたまましばらくすると、その長さが「ふだんの
長さ」になる**（形をおぼえ直す）。伸びきったバネは消え、近づいた粒には
新しいバネができる。

**③ バネはご近所より遠くまで届く**
はじめ、バネは近い粒どうししかつなげず、少し離れたら即切れていた。だから
引っぱるとすぐちぎれ、本体は形を変えなかった。実際のスライムがよく伸びる
のは、中に**長いひものような分子（ポリマー）**がからまっているから。その鎖
は遠くまで届く。そこでバネも、ふだんの間隔の**8倍**まで伸びてから切れる
ようにした。これで引くと**本体ごと伸びる**。

**④ つくえにねばりつく**
これがないと、引いたときスライム全部が持ち上がって飛んでいく。本物どおり
下は机に残るので、指のほうだけが伸びていく。

### ぜんぶひとりでに起きること

- 机の上でだんだん**びちゃっと広がる**（幅 9.2 → 20.7、高さ 9.2 → 2.6）
- 引くと**本体ごとびよーんと伸びる**
- 引きすぎると**ちぎれる**（判定は書いていない。粒のつながりが切れただけ）
- かけらを寄せると**くっついて1つに戻る**
- つつくと**へこみ、まわりに波が伝わる**（粒どうしのおしくらまんじゅうから）

配合から粘り・くっつく力・バネの強さ・形をおぼえ直す速さを決めているので、
同じ遊びでもスライムがちがえば動きがちがう。

### 速さ ― スマホで動かないと意味がない

はじめ 620粒で作って PC では 60fps だったが、**実機では遅すぎて遊べなかった**。
CPU を遅くして測りなおしたら、原因ははっきりしていた。

| | 直す前 | 直したあと |
|---|---|---|
| PC そのまま | 60fps | 61fps |
| CPU 4倍おそく（ふつうのスマホ） | **15fps** | **33〜58fps** |
| CPU 8倍おそく（古いスマホ） | **8fps** | **19〜39fps** |

効いたのは主に4つ。

1. **粒の絵を毎フレーム作りなおしていた。** `createRadialGradient` を粒の数だけ
   毎フレーム呼んでいた（620回/フレーム）。ぼやけた丸を**1枚だけ作って
   使いまわす**ようにした。これが一番大きい。
2. 粒を 620 → **300**、バネの上限 20 → 14、密度の計算 3回 → 2回
3. 1フレームを2回に分けて解いていたのを**1回**に
4. つながり調べを毎フレーム → **4フレームに1回**

さらに、**遅い機械では自動で軽くなる**ようにした。フレーム時間を見て3段階に
落ちる（粒を減らす／糸を描かない／いちばん軽い段では画面の読みもどしをやめる）。
行ったり来たりしないよう、1回変えたら2.5秒は変えない。

### バウンドだけは粒ではない

粒でやると、スライムは机にぺしゃっとつぶれるだけでほとんど弾まず、
どの配合でも同じ結果になってしまった（**本物もそうなのだが、遊びとして
差が出ない**）。そこだけは弾み具合を直に使う簡単な玉のままにしてある。

| スライム | 弾んだ高さ | 弾んだ回数 |
|---|---|---|
| ベタベタ | 3 | 2かい |
| びよーん | 9 | 4かい |
| カチカチ | **32** | **10かい** |

### そのほかやっていないこと

空気抵抗、渦、粒どうしの熱、3次元。格子法や本格的なSPHにすればもっと
本物に近づくが、スマホのブラウザで 60fps は出せない。

## 色は絵の具とおなじまざりかた

RGB をそのまま平均すると「あお＋きいろ＝はいいろ」になってしまう。
絵の具は赤・黄・青が三原色なので、**RYB の立方体を三次元で補間**して
実際の絵の具の見た目に合わせている（`mix.js` の `rybToRgb`）。

| 入れたもの | できる色 |
|---|---|
| あお ＋ きいろ | **みどり** |
| あか ＋ あお | **むらさき** |
| あか ＋ きいろ | **オレンジ** |
| あか ＋ しろ | パステルあか |
| ぜんぶ | ちゃいろ |

絵の具の合計が多いほど色が濃くなる。しろ・くろ・フォームで明るさが動く。

## 確かめたこと

- あお＋きいろ＝みどり など、絵の具どおりの色になること
- たらした絵の具がまざらずにその場に残り、なぞったところから
  まざりはじめること（まぜる前 0.00 → まぜたあと 0.88）
- つぶの平均が実際の配合と一致していること（＝ボウルの色と
  できあがりの色がずれない）
- スライムが300粒でできていて、引くと本体ごと伸びること
- ちぎれたかけらを寄せると1つに戻ること
- ホウ砂水の量だけを変えて、はずみ（3/9/32）に差が出ること
- **CPU を 4倍・8倍おそくしても遊べること**（15→33fps、8→19fps）
- 3モード × 900×460 / 667×375 / 568×320 / 1280×720 で
  作る→あそぶ→たなに残す まで通してエラーが出ないこと
